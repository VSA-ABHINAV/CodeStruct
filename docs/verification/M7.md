## Scope & Objective (CS-015 & CS-017)

### CS-015: Effective Incremental Parse Caching
1. **Production Worker & Analysis Integration (`worker.py`, `python_parser.py`)**:
   - Integrated persistent per-file parse caching (`PersistentFileParseCache`) into `run_analysis_worker` where repeated project analyses actually execute.
   - Preserved existing whole-result cache (`cache_results` in `sqlite_repository.py`), ensuring cold analyses populate both caches and warm whole-project requests return HTTP 200 cache hits without running jobs.
2. **Deterministic Multi-Factor Cache Keys & Policy Fingerprinting (`file_cache.py`)**:
   - Cache keys strictly bind:
     - Canonical root identity (`os.path.normcase(str(Path(root).resolve()))`)
     - Normalized relative path (`relative_path.replace("\\", "/").strip("/")`)
     - Content SHA-256 digest (preventing stale reuse on same-size edits or touched mtimes)
     - Parser version (`PARSER_VERSION = "2"`)
     - Parse policy fingerprint (`source_grammar`, `max_file_size`, `single_file_name`)
3. **Bounded Capacity, Concurrency & Corruption Recovery (`file_cache.py`, `schema.py`)**:
   - Table `file_parse_cache` managed in SQLite WAL mode with index on `last_accessed_at` and compound index on `(root_identity, relative_path)`.
   - Enforces configurable LRU eviction when entries exceed `max_entries` (default 5,000) or total bytes exceed `max_bytes` (default 50 MiB).
   - Corruption recovery gracefully catches deserialization errors, removes corrupted rows, records cache misses, and falls back to clean uncached parsing.
   - Connection lifecycle managed via `@contextlib.contextmanager` ensuring explicit connection closure on Windows.

### CS-017: Bounded, Deterministic Graphviz Exports
1. **Canonical Graphviz DOT Generation & Safe Escaping (`export_dot.py`)**:
   - Strict character-level escaping (`_escape`) for double quotes, backslashes, newlines, carriage returns, tabs, and ASCII control characters.
   - Deterministic node and edge ordering (sorted by identifier and relationship tuples).
   - Bounds enforcement rejecting graphs exceeding `MAX_EXPORT_NODES=2000` or `MAX_EXPORT_EDGES=5000` with `GraphTooLargeForExportError`.
2. **Optional Subprocess Rendering with Strict Bounds (`export_dot.py`)**:
   - Subprocess rendering to SVG and PNG using argument arrays (`shell=False`) with timeout (`DEFAULT_RENDER_TIMEOUT = 15.0s`) and output size capping (`MAX_RENDER_BYTES = 10 MiB`).
   - Clean Win32 Toolhelp process-tree termination (`_kill_process_tree`) on timeout or errors.
   - Signature verification validating SVG root elements (`<svg`) and PNG magic headers (`\x89PNG\r\n\x1a\n`).
3. **Actionable Diagnostics & Optional Dependency Handling (`analyses.py`)**:
   - Graphviz remains strictly optional; unconfigured or missing `dot` executable raises `GraphvizNotFoundError`, cleanly mapped to HTTP 503 `GRAPHVIZ_UNAVAILABLE` with clear installation and configuration instructions.
   - Supported endpoints: `GET /api/v1/analyses/{id}/export/dot`, `GET /export/svg`, `GET /export/png`, and `GET /export?format={dot|svg|png}`.
4. **Accurate Frontend Complete-Graph vs Loaded-Slice Semantics (`TopToolbar.jsx`)**:
   - TopToolbar differentiates exporting the visible/loaded slice (`{currentIdentity}-slice-graph.{json|dot}`) from exporting the complete canonical graph via backend API (`/api/v1/analyses/{id}/export/dot`).
   - Prevents misleading users into believing a partial paged slice represents the entire graph.

## Detailed Evidence

### 1. Incremental Parse Cache Architecture & Invariants (`file_cache.py`, `worker.py`)
- **Key Determinism**: `compute_file_cache_key()` produces identical SHA-256 hashes for identical inputs and uniquely different keys for modified content, different parse policies, different parser versions, or different root paths.
- **Same-Size Invalidation**: Tested in `test_worker_parse_cache_end_to_end_invalidation` and verified in Scenario 3 of `verify_m7_cache_export.py`. Modifying file content while keeping size identical (e.g., 22 bytes) causes cache miss and automatic reparsing.
- **Timestamp Touch Resilience**: Verified in Scenario 4 of `verify_m7_cache_export.py`. Altering mtime without modifying content bytes hits the cache via content digest matching.
- **Cross-Root Isolation**: Identical filenames and content under different project roots produce distinct cache keys, preventing cross-project pollution.
- **Bounded LRU Eviction**: In `test_file_cache_lru_and_size_eviction`, inserting entries exceeding `max_entries` evicts the least recently accessed items first.
- **Corruption Recovery**: In `test_file_cache_corrupt_entry_recovery`, manually corrupting SQLite payloads results in safe recovery: cache miss logged, corrupt row deleted, and clean parse returned.
- **Database Migrations (`migrations.py`)**: Tested upgrading legacy schemas (v1, v2, v3) to schema version 4 (`file_parse_cache` table creation and LRU/lookup index creation). Verified schema validation rejection of missing metadata, future versions, and unsupported legacy versions.

### 2. Graphviz DOT, SVG, and PNG Exports (`export_dot.py`, `analyses.py`)
- **Deterministic DOT Output**: `graph_to_dot()` sorts nodes by string ID and edges by `(source_id, target_id, kind, id)` tuple, generating identical DOT strings regardless of input dictionary order.
- **Hostile Label Escaping**: Escapes quotes, backslashes, control characters, and newlines safely without allowing DOT statement injection.
- **Bounds Checking**: Enforces `MAX_EXPORT_NODES=2000` and `MAX_EXPORT_EDGES=5000`, rejecting oversized graphs with HTTP 400 `GRAPH_TOO_LARGE`.
- **Subprocess Isolation & Timeouts**: Renders via direct binary execution with `communicate(timeout=15.0s)` and output capping (`10 MiB`). On timeout, `_kill_process_tree` terminates all descendant processes cleanly.
- **Missing Graphviz Diagnostics**: When Graphviz is not installed or unconfigured, endpoints return HTTP 503 `GRAPHVIZ_UNAVAILABLE` with clear diagnostic instructions (`Install Graphviz and ensure 'dot' is in PATH or set CODESTRUCT_GRAPHVIZ_DOT_PATH`).
- **Signature Verification**: Validates `<svg` root tags for SVG exports and `\x89PNG\r\n\x1a\n` headers for PNG exports before returning HTTP 200.

### 3. Frontend Export Behavior (`TopToolbar.jsx`)
- Differentiates loaded/visible slices from complete canonical graph exports:
  - Slice export downloads `{currentIdentity}-slice-graph.{json|dot}`.
  - Complete graph export opens `/api/v1/analyses/{analysis_id}/export/dot` via API.
- Preserves all Lovable visual styling and layout integrity.
