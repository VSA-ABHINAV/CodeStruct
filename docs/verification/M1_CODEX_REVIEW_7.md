## Blocking findings

1. **Stale STOP disables a newer editor session.** New `_nav_queue` entries are `("STOP", None)` with no generation/token. In `_do_poll`, a 403 or URL error from generation 1 enqueues STOP even if generation 2 has started. `_poll_navigate` for generation 2 drains it *before* validating current generation and sets global `_nav_poll_active=False`. This permanently stops the new session. `docs/verification/M1_review7_queue_probe.py` reproduces `New session active after old STOP: False` without network or GUI. The smoke's claimed `session switching` changed active editor tabs and called `_execute_navigate` with stale strings; it did not register a second capability during an in-flight old poll, so it did not cover this race. Make STOP generation/token-scoped, discard stale messages without terminating the current poller, clear/ignore old queued commands on switch, and add a deterministic regression that orders old HTTP failure after new registration. Preserve Tk main-thread-only work.
2. **Windows Vite watcher fix targeted an inactive config.** `frontend/package.json` invokes plain `vite`; the current app config is `frontend/vite.config.js` (React plugin, base and `/api` proxy). The added `frontend/vite.config.ts` imports `@lovable.dev/vite-tanstack-config`, which is absent from this app's `package.json`, and contains the `bun.lock` watch-ignore claimed in the report. Remove/consolidate the stray config and place any needed watcher setting in the actual JS config, preserving React plugin, proxy and base. Verify which config Vite loads in a bounded dev start and that it serves the API proxy. Do not migrate frontend frameworks or redesign UI in M1.
3. **Credential-bearing smoke artifact left behind.** External scratch `session_info.json` still contains the complete capability `session_token` and viewer URL. The report describes evidence as redacted and cleanup complete. Do not copy token into review reports. Remove or redact this task-created scratch artifact after checking it is not needed by running processes, and update harness to avoid retaining credentials after smoke. Preserve the redacted summary/screenshots.

Record corrected evidence and focused tests in `M1_CORRECTIONS_7.md`, then stop for review. M2 must not begin. No contract rewriting or unrelated feature work.
