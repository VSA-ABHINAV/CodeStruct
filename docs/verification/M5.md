## Corrections for Codex Review 1 Findings

### Finding 1: Target Execution in Killable Isolated Child Process, Output Bounds & Side-Effect Prevention (CS-012)
- Implemented `codestruct.analysis.runtime_worker` subprocess module invoked via `python -m codestruct.analysis.runtime_worker <payload_file>`.
- Isolated target execution so `sys.argv`, `sys.path`, and globals cannot pollute or race the backend parent process.
- Implemented `CappedStream` for stdout and stderr to prevent unbounded memory consumption from target streams.
- Stream redirection to temporary log files inside `tmp_dir` prevents OS pipe buffer deadlocks on large outputs and ensures zero stream pollution into parent stdout/stderr.
- Capped exception error messages to `max_output_bytes` to prevent unbounded error memory consumption.
- Implemented Win32 Toolhelp snapshot process-tree discovery and recursive termination (`taskkill /F /T /PID <pid>` and per-PID `taskkill /F /PID <child>`) in `_kill_process_tree()` to guarantee all spawned descendants are terminated upon timeout or cancellation.
- Added deterministic regression tests in `tests/test_dynamic_tracer.py`:
  - `test_trace_project_target_timeout_prevents_side_effects`: Proves a target attempting post-timeout writes is killed with zero side effects.
  - `test_trace_project_target_cancellation_prevents_side_effects`: Proves a target canceled during execution is killed with zero side effects.
  - `test_trace_project_target_output_bounds_no_leak`: Proves a target emitting 400 KB of stdout/stderr runs to completion within enforced `max_output_bytes` without hanging or leaking.
  - `test_trace_project_target_error_output_capped`: Proves exception error text exceeding limits is capped to `max_output_bytes`.

### Finding 2: Ambiguous Symbol Disambiguation & Candidate Preservation (CS-013 / CS-014)
- Fixed `find_node()`: when multiple candidates match and line span is not unique, returns `(None, Confidence.LOW, "AMBIGUOUS_RUNTIME_MATCH", candidate_ids)` instead of arbitrarily returning `candidate[0]`.
- Fixed `merge_runtime_trace_into_graph()`: node-level stats (`runtime_invocations`, `runtime_calls_out`) are only updated when `callee` is uniquely resolved (`callee is not None`). For ambiguous targets, creates a `RelationshipKind.CALLS` edge with `target_id = None`, `target_reference = event.callee_name`, `resolution.status = ResolutionStatus.AMBIGUOUS`, and `resolution.candidate_ids = tuple(...)`. No candidate node's attributes are mutated.
- Added regression test `test_merge_runtime_trace_ambiguity_retention` asserting candidate nodes have 0 runtime invocations and edge retains `candidate_ids`.

### Finding 3: Truthful Overhead and Per-Event Duration Measurement (CS-013)
- Implemented microsecond instrumentation overhead tracking (`_hook_overhead`) during `_profile_callback` execution.
- Implemented per-thread call-stack duration tracking (`_call_stacks`, `_durations`) recording true `duration_seconds` on each `RuntimeCallEvent` and strictly positive `overhead_seconds` on `RuntimeTraceResult`.
- When 0 calls occur, `overhead_seconds` is `0.0`. For recorded calls, `overhead_seconds > 0.0`.
- Added unit test `test_dynamic_tracer_truthful_overhead_and_duration`.

## Detailed Evidence

### 1. Static Non-Execution vs Explicit Opt-In Execution (CS-012)
- Static analysis jobs submitted via `POST /api/v1/analyses` strictly parse AST without executing target code (`tests/test_v1_api.py::test_spawned_analysis_graph_diagnostics_and_non_execution`).
- Explicit opt-in runtime analysis executed via `POST /api/v1/analyses/{analysis_id}/runtime` runs bounded dynamic profiling under `DynamicTracer` in an isolated child process restricted to authorized project roots.
- Escaping relative paths (e.g., `../outside.py`) and non-existent targets are rejected with HTTP 400 (`RUNTIME_PATH_OUTSIDE_PROJECT`, `TARGET_NOT_FOUND`).
- Session history is recorded and queryable via `GET /api/v1/analyses/{analysis_id}/runtime`.

### 2. Attribution, Disambiguation, and Ambiguity Retention (CS-013)
- `DynamicTracer` captures profiling events on both main and spawned threads (`threading.setprofile` + `sys.setprofile`).
- Multi-threading, exception tracking, generator suspension (excluding normal generator yields from exception flags), and coroutine events are cleanly captured without leaking hooks.
- Recursive function invocations (`fact(n) -> fact(n-1)`) create valid self-loop `RelationshipKind.CALLS` edges with `recursive: "true"`.
- Same-named methods across classes in the same module are disambiguated by definition line spans.
- Indistinguishable candidates retain ambiguity under `ResolutionStatus.AMBIGUOUS` with `Confidence.LOW`, reason `"AMBIGUOUS_RUNTIME_MATCH"`, `target_id = None`, and `candidate_ids`.

### 3. Repeat-Run Metric Enrichment & Truthful Provenance (CS-014)
- `enrich_nodes_with_metrics` refreshes all topological metrics (centrality, fan_in, fan_out, components, cycles, stability) over combined static + dynamic edges without retaining stale previous values, while preserving custom node attributes (`runtime_invocations`, `runtime_calls_out`, `runtime_exception`).
- Repeated trace executions sum edge-level `runtime_calls` and node-level `runtime_invocations` without generating duplicate edges or corrupting evidence identifiers.
