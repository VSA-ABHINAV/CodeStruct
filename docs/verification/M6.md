## Scope & Objective (CS-016)

Implement and verify Milestone 6 issue **CS-016** ("Grounded semantic explanations, bounded retrieval, and strict validation"):
1. **Bounded Retrieval Layer (`retrieval.py`)**:
   - Assemble authorized source snippets, canonical graph relationships, runtime observations, topological metrics, and evidence IDs for explanations.
   - Enforce path containment within authorized project roots (`is_safe_path_contained`) to prevent directory traversal or outside-project leaks.
   - Strictly exclude secrets, credentials, API keys, tokens, and sensitive files (`is_secret_or_sensitive`).
   - Enforce file/count/byte/token limits (`max_tokens_budget`, `max_lines`, `max_bytes_per_file`, `max_relationships`, `max_runtime_events`).
2. **Strict Output Validation & Claim Provenance (`llm_summary.py`)**:
   - Validate provider output with strict Pydantic models (`extra="forbid"`) rather than permissive dictionary `.get()` parsing.
   - Validate all evidence references against the retrieved canonical evidence set (`validate_evidence_references`), rejecting unknown/hallucinated evidence IDs.
   - Distinguish observed facts from interpretations and label model-derived claims as `LLM_INFERRED`.
3. **Explicit Opt-In & Deterministic Offline Fallback (`llm_summary.py`, `analyses.py`)**:
   - Keep semantic generation optional and explicitly chosen (default `provider="rule-based"`).
   - Preserve a deterministic offline rule-based fallback when the provider is disabled, unconfigured (`CODESTRUCT_LLM_API_BASE` unset), times out, or returns invalid/hallucinated data.
   - Zero paid or remote provider calls during tests; use local injected fake providers (`FakeExplanationProvider`).
4. **Truthful API Metadata & Contract Alignment (`schemas.py`, `analyses.py`, `node_explanation.json`)**:
   - Return truthful provider, inference, evidence, and fallback metadata via `GET /api/v1/analyses/{analysis_id}/nodes/{node_id}/explain`.
   - Update API schemas, route handlers, and frontend contract fixtures.
5. **Static Analysis Non-Execution & Non-Provider Invariant**:
   - Ensure static analysis jobs (`POST /api/v1/analyses`) strictly parse code and compute topological graphs without invoking semantic providers or explanation generators (`tests/test_static_analysis_invariant.py`).

## Detailed Evidence

### 1. Bounded Authorized Retrieval & Path Containment (`backend/src/codestruct/analysis/retrieval.py`)
- **Containment & Traversal Defense**: `is_safe_path_contained(file_path, project_root)` resolves both target and root paths, asserting canonical root containment (`target.is_relative_to(root)`). Rejects `..` path traversals, drive root escapes, and relative escapes with `SafeRetrievalError`.
- **Sensitive Key & Secret Exclusion**: `is_secret_or_sensitive(file_path)` scans file paths against sensitive token patterns (`secret`, `credential`, `password`, `token`, `api_key`, `private_key`, `.env`, `.pem`, `.key`, `id_rsa`, `id_ed25519`). Excluded files return safe sentinel comments (`# [Excluded sensitive file: ...]`) and are omitted from snippet context.
- **Strict Byte, Line & Token Bounds**: `retrieve_source_snippet()` truncates lines exceeding `max_lines` (default 60) and bytes exceeding `max_bytes` (default 4096), appending explicit truncation indicators.
- **Multi-Source Context Assembly**: `retrieve_evidence_context()` aggregates:
  - Definition source snippet (`EvidenceKind.SOURCE_DEFINITION`)
  - Canonical graph incoming and outgoing relationships (`EvidenceKind.RELATIONSHIP`)
  - Runtime dynamic execution events from trace history (`EvidenceKind.RUNTIME_EVENT`)
  - Computed topological metrics (centrality, fan-in/fan-out, cycle participation, stability, community) (`EvidenceKind.METRIC`)
  - Bounded token budget enforcement with proportional token estimation (`estimate_tokens`).

### 2. Strict Pydantic Models & Citation Grounding (`backend/src/codestruct/analysis/llm_summary.py`)
- **Strict Parsing Models**:
  - `ExplanationClaim`: Defines `claim_text`, `evidence_ids: list[str]`, `provenance: ClaimProvenance` (`LLM_INFERRED` or `RULE_SYNTHESIZED`), and `confidence: float`. Uses `model_config = ConfigDict(extra="forbid")` to strictly reject unexpected properties or hallucinated top-level keys.
  - `LLMExplanationPayload`: Defines `summary`, `architectural_role`, `responsibilities`, `confidence`, `evidence_references`, and `claims`. Uses `model_config = ConfigDict(extra="forbid")`.
- **Canonical Citation Grounding**:
  - `validate_evidence_references(payload, retrieved_evidence_ids)` cross-references every evidence ID in `evidence_references` and in each claim's `evidence_ids` against the set of retrieved canonical IDs.
  - If any unknown or unretrieved ID is detected, validation fails immediately with `InvalidCitationError`, triggering automatic safe fallback to rule-based explanation with `fallback_reason` recording the rejected IDs.
- **Provenance Distinction**:
  - Model-generated claims from custom or OpenAI-compatible LLMs are explicitly labeled `ClaimProvenance.LLM_INFERRED`.
  - Rule-synthesized fallback claims are labeled `ClaimProvenance.RULE_SYNTHESIZED`.
  - Never conflates model inference with observed static or runtime facts.

### 3. Explicit Opt-In & Deterministic Offline Fallback (`backend/src/codestruct/api/routes/analyses.py`)
- **Opt-In Default**: The endpoint `GET /api/v1/analyses/{analysis_id}/nodes/{node_id}/explain` defaults to `provider="rule-based"`.
- **Fallback Triggers**: When `provider="llm"` or `provider="auto"` is requested:
  - If `CODESTRUCT_LLM_API_BASE` is unset -> Falls back to rule-based with `fallback_reason="LLM provider requested but not configured (CODESTRUCT_LLM_API_BASE unset)"`.
  - If custom provider times out -> Falls back to rule-based with `fallback_reason="Custom provider failed: TimeoutError: ..."`
  - If custom provider hallucinates invalid evidence IDs -> Falls back to rule-based with `fallback_reason="Provider cited invalid or unknown evidence IDs: [...]"`
  - If custom provider returns malformed or non-JSON schema -> Falls back to rule-based with schema validation error reason.
- **Truthful Response Metadata**:
  - `fallback_used: bool`
  - `fallback_reason: Optional[str]`
  - `retrieved_evidence_ids: list[str]`
  - `cited_evidence_ids: list[str]`
  - `claims: list[ExplanationClaimModel]` with `provenance` and `confidence`

### 4. Non-Execution & Non-Provider Static Analysis Invariant
- Verified in `tests/test_static_analysis_invariant.py` that static analysis jobs (`POST /api/v1/analyses`) do not invoke `explain_node`, semantic providers, or LLM services. Static graph generation remains 100% deterministic, AST-based, and offline.
