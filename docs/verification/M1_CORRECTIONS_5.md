## 2. Detailed Technical Breakdown

### 2.1 Item 1: Full-Graph Default Cap (4 MiB)

**Problem:**
Sections 5.5 and 5.6 of `LOVABLE_FRONTEND_BRIEF.md` previously claimed that `max_full_graph_bytes` defaults to 10MB. In reality, both `Settings.max_full_graph_bytes` (`backend/src/codestruct/settings.py:74`) and `load_settings()` default to `4 * 1024 * 1024 = 4194304 bytes (4 MiB)`, configurable via environment variable `CODESTRUCT_MAX_FULL_GRAPH_BYTES`.

**Resolution:**
1. Updated Section 5.5:
   ```markdown
   - `GRAPH_TOO_LARGE` (413): Complete unpaged graph exceeds `max_full_graph_bytes` (default 4194304 bytes / 4 MiB, configurable via `CODESTRUCT_MAX_FULL_GRAPH_BYTES`); request a bounded page.
   ```
2. Updated Section 5.6:
   ```markdown
   - **Omitted `limit` (Full Graph):** When `limit` is omitted, the server returns the complete unpaged graph. This request is governed by `max_full_graph_bytes` (default 4194304 bytes / 4 MiB, configurable via `CODESTRUCT_MAX_FULL_GRAPH_BYTES`), NOT by `max_graph_page_size`. If the full graph exceeds `max_full_graph_bytes`, the server returns HTTP 413 `GRAPH_TOO_LARGE`, instructing the client to paginate.
   ```
3. Added regression test `test_brief_full_graph_bytes_default_matches_settings` in `tests/test_contract_fixtures.py`:
   - Extracts documented defaults from Sections 5.5 and 5.6 via regex.
   - Compares against `Settings(authorized_roots={}).max_full_graph_bytes` and `load_settings().max_full_graph_bytes`.
   - Asserts exact equality to `4194304`.
4. Production backend settings and pagination logic were preserved untouched.

### 2.3 Item 3: Nullable Diagnostic Location, References & Degradation

**Problem:**
Section 5.7 guaranteed that every diagnostic item has a structured `location`. In actual operation, scanner-level exclusions, whole-file encoding failures, or structural cycle diagnostics have `location: null`. Furthermore, `entity_id` and `edge_id` are nullable, and span endpoints (`end_line`, `end_column`) are optional.

**Resolution:**
1. Updated Section 5.7 guarantees in `LOVABLE_FRONTEND_BRIEF.md`:
   ```markdown
   > **Diagnostic Field Guarantees & Nullability:**
   > - **Canonical Fields:** Each diagnostic item includes canonical `id`, `code`, `severity` (`info` | `warning` | `error`), `phase` (`scanning` | `parsing` | `resolving` | `building_graph` | `computing_metrics`), `message`, `recoverable`, `consequence`, `suggested_action`, and `details`.
   > - **Nullable Location & References:** `location` is nullable. Whole-file encoding failures, scanning exclusions, or structural graph-level cycles have `location: null`. Likewise, `entity_id` and `edge_id` are nullable and populated only when a specific graph element is associated. Furthermore, span endpoints (`end_line`, `end_column`) within `location` are optional and may be null or 0.
   > - **Navigation Degradation:** When `location` is `null` or lacks valid start line coordinates (`start_line`), editor source cross-navigation is disabled while diagnostic text, severity badges, and details are displayed in full. Clients must not fabricate fake file paths or line numbers when `location` is `null`.
   ```
2. Frontend implementation verification:
   - `frontend/src/features/architecture/graphContract.js`: `location(value)` safely returns `null` when `value` is null or invalid. `text(item.entity_id)` and `text(item.edge_id)` return `null` when null.
   - `frontend/src/features/architecture/DiagnosticsDrawer.jsx`: `item.location` check guards location rendering (`{item.location && <p className="cs-drawer__loc">...}`).
   - `frontend/src/features/architecture/DiagnosticsPanel.jsx`: Displays `'No source location'` when `item.location` is null.
   - `frontend/src/features/architecture/DetailsPanel.jsx`: `formatSpan` returns `'Unavailable'`; `open-in-editor` button is rendered only when `onNavigateSource && item.location?.path && item.location?.startLine != null`.
   - `frontend/src/App.jsx`: `handleNavigateSource` returns error alert `'Editor navigation unavailable: Selected element has no source location.'` if path or line is missing.
3. Added frontend contract normalization test in `frontend/src/api/contractFixtures.test.js`:
   - Passes real static locationless diagnostic (`FILE_ENCODING_FAILURE`, `location: null`, `entity_id: null`, `edge_id: null`) through `normalizeGraphContract`.
   - Verifies normalized `location === null`, `entityId === null`, `edgeId === null`, without errors or fabricated paths/lines.
4. Added backend test `test_diagnostics_nullable_location_and_parser_fixture` in `tests/test_contract_fixtures.py`:
   - Statically parses `tests/fixtures/parser_project` (never executed).
   - Verifies 5 locationless diagnostics (`FILE_ENCODING_FAILURE`, `PATH_EXCLUDED`, `INHERITANCE_CYCLE`).
   - Validates that `DiagnosticsResponse` accepts and serializes locationless diagnostics.
