## 3. CS-020: Reproducible Accuracy and Performance Evaluation

### Evaluation Methodology
- **Ground Truth Definition:** Four distinct benchmark projects were authored under `tests/fixtures/ground_truth/`, spanning single-package small utilities up to multi-tiered layered services with type stubs (`.pyi`). Each benchmark has an exact count of ground-truth entities (modules, classes, functions, methods, files) and relationships (imports, resolved calls, inheritance, constructs, defines) recorded in `ground_truth_manifest.json`.
- **Normalization and Matching:**
  - Entities matched by normalized `qualified_name` and `kind`.
  - Relationships matched by `(source_qualified_name, target_qualified_name, kind)`.
  - Dynamic attribute lookups (`getattr(obj, name)()`) and dynamic reflection are treated as unresolved/ambiguous per static analysis design invariants.
- **Repeat Methodology:** Wall-clock analysis times and Graphviz DOT export times were measured over 3 iterations per project to compute mean and sample standard deviation. Memory was tracked using Python's `tracemalloc` to report peak allocations during analysis. Dynamic tracing was evaluated using `DynamicTracer` attached to benchmark execution via `sys.setprofile`.

*Finding:* Python CPython `sys.setprofile` hooks incur ~150–1000 ms absolute profiling overhead for short execution loops (attributable to Python-level frame inspection and call-stack accounting per event). Because runtime tracing is an explicit, opt-in developer capability (`POST /api/v1/analyses/{id}/runtime`) never enabled during standard static analysis, this overhead is fully isolated and does not affect the sub-100 ms static analysis pipeline.

### Documented AST and Resolver Limitations
1. **Dynamic Attribute Lookup:** Functions called via `getattr(target, method_name)()` cannot be statically resolved without runtime symbol values; they are marked `AMBIGUOUS` or preserved as unlinked calls per design invariants.
2. **Dynamic Code Execution:** Constructs like `eval()`, `exec()`, or dynamic runtime class construction (`type("Foo", ...)`) are not executed or analyzed.
3. **C-Extensions and Built-ins:** Compiled native C-extensions (`.pyd`, `.so`) have no AST source files; they resolve to `EXTERNAL` boundaries.
4. **Metaprogramming:** Python `__getattr__` and `__getattribute__` proxy dispatches are not traced statically.

| **Repository Transaction Rollback** | Simulated exception raised midway during `save_analysis()` | Atomicity guaranteed: SQLite transaction rolls back; zero orphaned analyses, nodes, or edges remain | Database contains 0 records after failed insert; clean rollback confirmed | **PASS** |
| **Parse Cache Transaction Rollback** | SQLite constraint violation or simulated error during cache insert | Atomicity guaranteed: transaction rolls back completely; zero corrupted partial cache rows | Total cache count remains 0; no stale entries stored | **PASS** |
| **Corrupted SQLite Cache Signature** | Database row modified with bad SHA-256 digest or invalid payload | Corrupt cache detected; `CorruptCacheEntryError` raised; row marked `invalid=1` and committed; transparent fallback to fresh AST parse | Invalid flag committed to SQLite; cache lookup raises `CorruptCacheEntryError`; transparent rebuild | **PASS** |
| **Corrupted Disk File Cache Entry** | On-disk cache file overwritten with malformed non-JSON bytes | Detected on read; invalid file deleted from cache directory; transparent fresh parse succeeds | Malformed file evicted; subsequent reads recreate valid cache entry | **PASS** |
