## 2. Confirmed Root Cause Analysis

### Observed Error
```text
Previous configuration could not be read:
File contains no section headers.
file: ...configuration.ini, line: 1
'\ufeff[general]\n'
Using default settings
```

### Technical Root Cause
1. **PowerShell 5.1 UTF-8 Encoding Behavior:**
   In Windows PowerShell 5.1 (.NET Framework), using `[System.Text.Encoding]::UTF8` initializes a UTF-8 encoder with the Byte Order Mark enabled (`emitIdentifier = true`). When writing `configuration.ini`, it prepended the 3-byte sequence `0xEF 0xBB 0xBF`.
2. **Python `open()` and `configparser` Mechanics:**
   Thonny's `thonny/config.py` opens `configuration.ini` with `open(self._filename, "r", encoding="UTF-8")` and passes the stream to `configparser.ConfigParser().read_file()`. Standard Python `encoding="UTF-8"` (unlike `utf-8-sig`) does not strip the BOM, interpreting the first 3 bytes as character `\ufeff`.
3. **INI Parser Rejection:**
   `ConfigParser` expects the very first non-whitespace character to be `[` to indicate a section header. Seeing `\ufeff[general]`, it failed with `MissingSectionHeaderError`, causing Thonny to display an error modal and reset to defaults.
4. **Why Previous Tests Missed It:**
   Earlier tests validated HTTP endpoint responses and Python module importability without exercising Thonny's configuration loader lifecycle (`thonny.config.try_load_configuration()`) or inspecting the raw binary header bytes generated by PowerShell 5.1.

## 3. Exact Code Changes

### A. `prototype-launcher/Start-CodeStruct-Prototype.ps1`
- **Explicit No-BOM UTF-8 Encoding:**
  Constructed `$utf8NoBom = New-Object System.Text.UTF8Encoding($false)`.
- **Byte-Level Inspection & BOM Detection:**
  ```powershell
  $bytes = [System.IO.File]::ReadAllBytes($profileConfig)
  if ($bytes.Length -ge 3 -and $bytes[0] -eq 0xEF -and $bytes[1] -eq 0xBB -and $bytes[2] -eq 0xBF) {
      # Create safe timestamped backup before repair
      $timestamp = (Get-Date).ToString("yyyyMMdd_HHmmss")
      $backupPath = Join-Path $profileDir "configuration.ini.bom-backup-$timestamp"
      [System.IO.File]::Copy($profileConfig, $backupPath, $true)
      
      # Strip first 3 bytes and re-write pure UTF-8 without BOM
      $content = [System.IO.File]::ReadAllText($profileConfig, [System.Text.Encoding]::UTF8)
      [System.IO.File]::WriteAllText($profileConfig, $content, $utf8NoBom)
  }
  ```
- **Thonny Configuration Reader Preflight Check:**
  Added headless verification invoking `thonny.config.try_load_configuration()` to assert `error_reading_existing_file` is `None` before launching the IDE GUI.
- **Port Conflict Pre-Checks & Safe Rollback:**
  Pre-checks both ports (8000 & 5173) before starting any service, maintaining incremental state and rolling back only newly spawned processes upon failure.

### B. `frontend/vite.config.js`
